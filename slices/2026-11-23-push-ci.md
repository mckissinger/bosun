## Brief

Outcome: Without a merge queue, a PR tested against an older `main` is still checked against the combined code after it merges, here and in every project the conformance check reads.

Done-conditions:
P1. `done` `.github/workflows/checks.yml` also runs on `push` to `main`; the whitespace step compares a push against the commit before it (`github.event.before`) instead of the PR base, and only PR runs cancel superseded runs, so no push to `main` goes untested.
P2. `done` `scripts/ci-conformance.py` reports a FAIL when the merge setup is known, there is no merge queue, and no required check's workflow (any workflow defining that job) has a `push` trigger covering the default branch, and notes (INFO) a single required check that does not run there, since a diff-only check such as a security review need not; `skills/bosun-ci/SKILL.md` lists it among the FAILs and README's `/bosun-ci` paragraph names it.
P3. `done` Version 0.31.1 in both manifests and the README version line.
P4. `done` Checks pass: `bash -n scripts/*.sh`; JSON parses for both manifests and `hooks/hooks.json`; `python3 -m py_compile scripts/*.py`; `claude plugin validate .`; `git diff origin/main --check`; the project-name grep over added lines in rules, skills, agents, scripts, README.md and .claude-plugin finds nothing; the conformance check gives this repository 0 FAIL after P1, a fixture without the push trigger the new FAIL, and rv-rez and crelaunch their earlier results.

Out of scope:

Assumptions:
- **Cancellation.** Only PR runs cancel superseded runs, because a cancelled push run leaves that commit of `main` untested.
- **Versioning.** Patch bump: a new check of an existing rule (core "Merge setup" already requires CI on pushes without a queue).
